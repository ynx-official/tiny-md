## 问题与交互规则

用户反馈勾选任务复选框会跳回文首，超链接缺少可点击的鼠标提示。
GPUI 回归确认：复选框调用通用编辑流程后恢复旧文本光标，却仍请求滚动到该光标，
旧光标位于文首时就会拉回页面。旧实现同时清除了已有选区。

复选框现在只切换任务标记，保留文本光标、选区方向及当前滚动位置，仍发出修改通知并进入撤销历史。
普通模式与打字机模式采用相同的原位切换规则。只读复选框不响应切换，也不显示操作手形光标。

正文链接、可编辑复选框与可点击展开源码的流程图预览显示手形光标；既有复制、缩放、查看按钮保留原手形光标。
链接使用实际排版后的文字范围作为悬停和点击区域，每个换行单独命中，表格内链接保留单元格对齐。
Windows 使用 Ctrl+点击，macOS 使用 Cmd+点击；可编辑模式的普通点击仍定位文本光标，
只读模式普通点击即可激活链接。正文普通文字、链接周围空白与源码模式不激活预览链接。
URL 打开及其他链接目标的处理继续遵循应用原有规则。

## 自动验证

新增四项 `markdown_interaction_` 回归在修复前实际失败，修复后通过：

- `checkbox_keeps_the_scrolled_view`：80 行文档、文本光标在文首、滚动至第 56 行，
  普通 / 打字机模式连续勾选和取消均保持原偏移；检查 Markdown 文本、光标及撤销 / 重做。
  修复前实际偏移从 -1260 px 回到 -12 px。
- `checkbox_preserves_selection_and_change_events`：中文与 emoji 的反向选区保持方向，
  单次切换只发出一次正文修改通知；修复前选区变成空。
- `links_have_precise_regions_and_keep_editing`：链接存在独立交互区域，Ctrl / Cmd 点击激活，
  周围文字不误开链接，普通点击继续编辑，切到源码模式后不激活预览链接。
- `wrapped_table_links_work_in_read_only_mode`：320 px 宽窗口内的右对齐中文 / 英文 / emoji 链接，
  三个换行区域都能激活相同目标；只读复选框点击不修改文档。

`./scripts/check.ps1` 于 2026-10-09 通过：17 项 Python 发布工具测试、当前版本资料检查、
Rust 格式检查、161 项工作区测试（应用 53、文档 16、编辑器 77、更新器及其集成测试 15）及 Clippy。
原有一个编辑器示例 doctest 忽略。缓存、快速输入、组合输入及表格编辑的既有回归继续通过。

`cargo build --locked -p tiny-md` 成功生成 Windows 开发版 `target/debug/tiny-md.exe`。
`scripts/verify-windows-exe.ps1` 确认 x64 GUI 子系统与九个嵌入图标帧符合项目约定。

## 原生验收边界

自动验证使用 GPUI TestPlatform 的排版及鼠标事件路径，不能代替原生系统光标外观、GPU 绘制与真实鼠标验收。
Windows / macOS 原生检查仍需确认：滚动到长文档中下部后反复勾选、链接及复选框悬停手形、
普通文字悬停文本光标、跨行及表格内链接、只读 / 源码切换与流程图预览入口。
