# Mermaid 流程图解析兼容性

- 状态：Review
- 最后更新：2026-10-14
- 关联文档：[ELK 布局](../03-architecture/flowchart-elk-layout.md)、[加载性能](diagram-load-performance.md)、[缓存与调度](diagram-memory-and-viewer.md)

## 已复现的问题

用户提供的替岗转交流程是正常源码。`fixtures/diagrams/task-transfer.mmd` 保留完整样例，
预期 19 个节点、24 条连线，包含中文、`<br/>`、分支、循环与大写 `END` 节点。

固定版本 `mermaid-rs-renderer 0.3.1` 的严格校验器先将整行转为小写，
将 `END --> REVOKE[...]` 误认为子图结束，报告 `expected matching subgraph`。
错误发生在解析预检阶段，尚未进入 ELK。其实际流程图解析器只将裸的小写 `end` 当作结束，
因此预检与解析器的语义不一致。[Mermaid 官方说明](https://mermaid.js.org/syntax/flowchart.html)
明确允许 `End` / `END` 等含大写字母的写法。

另一个问题是带管道标签的链式连线。`A -->|否| B[说明] --> C` 在旧解析器中可能
漏掉 `B --> C`，并将 `B[说明]` 误作完整节点 ID。完整样例原先得到 20 个节点、22 条连线，
修复后的 19 / 24 才符合源文。此前性能记录将第 23 张错误归为“原有语法错误”不准确，
它实际是上述兼容性问题；历史计时的 34 成功 / 1 错误保留为当时的运行事实。

## 修正与约束

`mermaid_parse.rs` 统一处理渲染及诊断的解析入口，不修改上游 Cargo 注册表文件。
正常输入继续使用原严格解析入口。流程图中独立出现的 `END` / `End` 等节点，
只在校验副本中替换一个 ASCII 字节，保留上游行列号；真正的小写 `end` 仍参与子图闭合校验。
节点 ID、标签、样式和链接从真实源文取得，不改写文档、撤销历史或缓存键。

带标签的链式连接只在临时解析副本中展开为同一行的等价分号语句，
保留节点声明、各段箭头与标签的顺序。扫描忽略节点标签、单双引号内容与注释中的箭头、
管道和分号；识别普通文本中的英文撇号，跳过前置元数据。
继续执行上游校验，并补充目标流程图的节点括号检查，避免遗漏闭合或只画出半条链。
非流程图沿用原路径；没有宣称覆盖 Mermaid.js 的全部语法。

35 张图现在都能生成，200% DPI / 1000 逻辑像素下的目标像素合计约 293.31 MiB。
解析修正当时，原 256 MiB 正文缓存不足以完整复用该有效文档，复测稳定触发首图淘汰。
将默认有界预算调整为 384 MiB；SVG / 错误仍为 16 MiB，各最多 128 项，
系统字体仍最多 64 MiB，单张预览 / 高清像素上限仍为 64 MiB。
预算是淘汰上限，不是启动时预分配；LRU、取消、共享引用和共用 5 个计算名额的规则保留。
以上为解析修正及 v0.2.9 发布时的行为。用户后续取消闲置图形缓存但保留整篇预生成，
最新源码的资源生命周期与释放对照以[内存与独立查看](diagram-memory-and-viewer.md)为准。

## 双引号分支标签

用户提供的立项流程使用 `J -->|"Pivot"| B` 等写法。上游解析器保留了管道标签的语法双引号，
导致预览多显示一对引号。解析成功后，仅对流程图边标签移除一层匹配的外围双引号；
内层引号、转义与实体内容保留，源码、缓存键和撤销历史不变，其他图类型沿用原结果。
回归覆盖普通标签、带标签链、内部引号和已加引号的实体文本。
布局修正与本次验证见[流程图阅读顺序](flowchart-reading-order.md)。
