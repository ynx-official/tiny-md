# SVG 字体内存优化

- 状态：Review
- 最后更新：2026-10-27
- 关联文档：[图片预览](inline-images.md)、[流程图内存](diagram-memory-and-viewer.md)、[HTML 混排](html-compatibility.md)

## 已确认问题与范围

用户反馈打开文档后内存约 150 MB，确认先优化 SVG 的字体加载及字体缓存容量。保留原有 HTML 展示、中文输入、撤销、图片资源限制，以及流程图的整篇预生成、共享和并发策略。Windows / macOS 使用相同实现；本次实际运行环境为 Windows。

诊断发现普通 SVG 通过 `diagram_raster::options()` 取得字体库，首次加载一个小徽章也会预加载流程图使用的中文字库。原字体缓存用 `Vec::new()` 读取文件，按有效数据长度累计 64 MiB 预算；fontdb 将整个 Vec 长期保留，额外容量未释放、未计入预算。本机六份常用字体合计约 37.73 MiB，但缓冲区容量合计 68 MiB。

## 实现

- `svg_fonts.rs` 只共享系统字体索引与文件来源。普通 SVG 由 USVG 在解码时按需读取 / 映射实际使用的字体，生成位图后释放临时树及其字体资源，不启用流程图的常驻字库。
- 流程图使用索引的独立副本，继续保留原有常用字体加速缓存；不会把常驻字节写入普通 SVG 的共享索引。
- 字体读取根据文件长度预分配，并预留一次 EOF 探测空间，避免正常读取触发容量翻倍；仍使用有界读取处理文件长度变化。
- 缓存前通过 boxed slice 移除额外容量，再转换回紧凑 Vec；按实际容量扣减预算。文件超出预算、读取失败或解析失败时继续使用原有文件来源。
- SVG 尺寸限制、外部 / 嵌入资源禁用、RGBA / BGRA 转换及透明度处理保持原有行为。

## 内存对照

使用原生 Windows 开发构建、独立进程、相同后台启动方式采样。普通样例在启动后第 5、15 秒记录，完整用户样例在第 5、20 秒记录；下表为最后一次记录。每次只结束本轮创建的诊断进程。

后台窗口与前台交互的内存不必相同；本表用于相同条件的前后对照。工作集包含共享页面，不能与“私有工作集”或“私有提交量”混用。旧构建为优化前的 0.2.13，新构建沿用工作区已有的 0.2.14 版本元数据及相同开发配置；本优化未改变版本或依赖声明。

| 内容 | 优化前工作集 MiB | 优化后工作集 MiB |
|---|---:|---:|
| 空白文档 | 68.98 | 69.27 |
| 简单中文 Markdown | 70.02 | 69.52 |
| PNG Logo | 71.07 | 70.80 |
| 单个本地 SVG 徽章 | 139.76 | 71.16 |
| 用户完整 HTML 样例 | 152.54 | 79.52 |

完整样例工作集减少 73.02 MiB，约 47.9%；私有工作集由 95.93 降至 23.05 MiB，私有提交量由 198.07 降至 101.19 MiB。该结果属于这台机器、这份文档和当前构建，不是任意文档的固定上限。短时采样稳定，不作为长期泄漏检测结论。

样例为 [用户提供的 HTML 内容](../../fixtures/html-functional-markers.md)，包含本地 PNG Logo、四个远程 SVG 徽章、中文标题、注释与换行标记。单个 SVG 对照使用本地固定内容排除网络因素；完整样例保留原始地址，仍受网络与上游响应影响。

原始数据保存在本机构建目录，不纳入版本控制：

- `target/memory-diagnostics/native-memory.csv`：优化前进程采样。
- `target/memory-diagnostics/native-memory-after.csv`：优化后采样及附加的小型流程图对照；流程图加载完成状态未做原生界面确认，不用于流程图性能结论。
- `target/memory-diagnostics/font-capacity.log`：旧读取方式的字体长度 / 容量对照。

## 回归与验证

先通过失败测试复现两项问题：65,537 字节的数据保留 131,072 字节容量，以及普通 SVG 索引中存在流程图预加载的二进制字库。修复后验证紧凑容量、超预算回退、共享索引不持有常驻字库。

新增像素级对照覆盖英文徽章、显式中文字体及缺失字体的回退；与原流程图字体加载路径生成的位图逐字节一致。既有流程图文字、形状、透明度及深浅主题像素对比、HTML 混排、输入 / 撤销和保存回归继续通过。

最终执行 `./scripts/check.ps1`：273 项工作区测试通过（应用 74、文档 16、编辑器 168、更新器 15）；17 项发布工具测试、版本资料、格式检查和 Clippy 均通过。原有 2 项手工性能测试及 1 项 doctest 保持忽略。Windows 开发构建通过。

首轮全量运行中，既有图片缺失后重试测试在检查时仍处于加载状态而失败；未修改断言，独立复测和后续两次全量测试运行均通过。另修正了 Clippy 指出的 Options 初始化写法，最终标准检查完整通过。

最终日志：`target/memory-diagnostics/font-memory-workspace-final.log`、`target/memory-diagnostics/font-memory-build.log`。本次不使用 Computer Use 操作用户界面；像素与输入测试来自 GPUI TestPlatform。macOS 尚无本次构建或原生运行证据，系统输入法未重新实测。
