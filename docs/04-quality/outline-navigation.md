# 大纲章节定位

- 状态：Review
- 最后更新：2026-10-14
- 关联文档：[UI 风格](../02-design/ui-style.md)、[正文滚动条](document-scrollbar.md)

## 已确认行为

用户要求点击大纲后从对应章节开头继续向下阅读。章节起点应尽量对齐正文视口顶部，
不因跳转方向而改变；已在视口中的章节及重复点击当前章节也应用此规则。
文首和文末受实际滚动范围限制，不为顶端对齐追加文末空白。

排版、源码与打字机模式共用这项导航行为，标题自身留白与字号保持既有配置。
点击后继续聚焦编辑器，移动光标并清除选区，不修改正文、未保存状态或撤销历史。
普通输入、方向键与打字机模式的编辑滚动继续使用原有光标可见 / 居中规则。

## 根因与实现

原大纲点击调用通用 `edit` 移动光标，然后由 `ensure_cursor_visible` 做最小滚动：
目标在上方时移动到顶部，在下方时只移动到光标刚好进入底部的位置，目标已可见时不滚动。

编辑器新增 `jump_to_line` 导航接口，使用一次性的章节起点对齐请求。
在当前排版行布局完成后计算目标行位置，以 12 px 的正文内部留白对齐其起点；
打字机模式导航时抵消其较大的顶部内边距。GPUI 在布局阶段根据最新内容高度限制偏移。
应用大纲点击改用该接口；普通编辑、输入法与其他光标操作仍请求原有可见性调整。
Windows 与 macOS 共用实现。

## 回归验证

通过 GPUI TestPlatform 实际大纲鼠标点击、窗口布局、编辑器输入范围坐标和共享滚动状态验证。
实现前，向下跳转后标题距视口顶部约 346 px，已可见标题点击后仍为 83 px，
文末跳转也未达到最大滚动范围，三项回归均失败。

| 场景 | 断言 |
|---|---|
| 多章节上下跳转、文首、重复点击 | 章节标题靠近正文顶部，光标位于目标行且编辑器获得焦点 |
| 排版、源码、打字机模式 | 使用相同的章节起点对齐规则；正文及未保存状态保持一致 |
| 已经可见的章节 | 点击后仍重定位至顶部，方便向下阅读 |
| 文末只有少量内容 | 偏移限制在文档最大可滚动范围，末章仍可见 |

2026-10-14 实际运行结果：

- `cargo test --locked -p tiny-md outline_navigation -- --nocapture`：3 项通过。
- `./scripts/check.ps1`：工作区测试、17 项 Python 发布工具测试、当前版本资料校验、
  Rust 格式检查及 `cargo clippy --locked --workspace --all-targets -- -D warnings` 均通过。
- `cargo build --locked -p tiny-md`：Windows 开发构建通过，产物为 `target/debug/tiny-md.exe`。
