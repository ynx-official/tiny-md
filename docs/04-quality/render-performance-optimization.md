# 长文档渲染性能优化

- 关联文档：[优化前测量](render-performance-analysis.md)、[外部同步](../02-design/external-file-sync.md)、[验证记录](../verification.md)

## 实现与范围

按用户确认的五项顺序实施，沿用 Rust / GPUI / Guise、现有主题和排版。

1. **光标独立绘制。** 正文在 `DocumentLayer` 中使用 GPUI 缓存；显隐只通知 `CaretLayer`。
   光标在滚动视口外时不请求绘制。正文编辑、焦点、选区、源码模式和主题变化仍使正文失效。
2. **结构与行布局缓存、视口裁剪。** 未变化的文档复用结构；插入 / 删除行后迁移未改变的前后行缓存。
   缓存键包含字体、颜色、宽度、块语法、代码内容、表格列宽、揭示范围、当前单元格及选区状态。
   只为可见区和上下各一屏缓冲区创建节点，以上下占位保留完整滚动高度。
3. **减少无用排版。** 表格数据行直接使用单元格布局；隐藏的分隔行、围栏和 Mermaid 源码不排版文字。
   不再先排版整行表格源码再丢弃结果。
4. **保留模式缓存。** 正文 / 源码各自保存行布局；模式切换保留代码高亮、Mermaid 图像、缩放与横向滚动状态。
   源码编辑导致实际内容或围栏状态改变时，相关布局重新生成。
5. **后台检测与统计。** 保存基准和原始字节使用共享快照，克隆不复制全文。
   `notify 7.0.0` 监听文件父目录，覆盖原子替换；事件过滤后合并为一个待处理标记，每 150 ms 检查。
   无事件时每 5 秒完整字节核对，支持事件缺失或监听不可用的文件系统。
   忙碌 / IME 期间保留待处理标记，异步结果过期后重试；保存前仍强制核对字节与三方合并。
   字符统计只重新计数改变的行；普通段落输入复用目录，标题、围栏、Front Matter 或行数变化立即更新目录。

初次打开、窗口换宽、字体变化仍测量全部行的高度；缓存保留完整光标 / IME 映射。
每次文本变更仍完整更新文档结构和源码高亮状态，以保证围栏 / 表格上下文正确；未改变的行复用字体布局。
本次未引入屏外高度估算，避免估算修正引起滚动跳位。简介仅扫描原来的前三个有效行，保持原行为。

## 自动化证据

`render_cache` 的回归先复现缓存不复用、插入行丢失布局、可见行范围错误四项失败，再实现缓存。
共享快照与增量统计先复现全文复制和全文重复计数；文件调度先复现空闲 tick 仍读取。
GPUI 实际渲染回归另发现 cached view 在 prepaint 中通知丢失，缩放后未及时重排；
宽度探针改为绘制完成后通知，缩放 / 字体 / 主题回归通过。

自动化覆盖正文缓存后的真实 GPUI 布局、绘制与事件路径，但使用 TestPlatform 字体 / 窗口，并非 Windows GPU 或系统输入法验收。

| 场景 | 结果 |
|---|---|
| 400 行文档光标层显隐 | 正文 render、文档解析、文本排版、行节点构建计数均不增加 |
| 滚动 | 不重新解析或排版；光标与 IME 范围坐标保持一致，视口外光标不请求刷新 |
| 正文 → 源码 → 正文 | 不增加文档解析、正文 / 单元格排版计数；Mermaid 图像身份、缩放及高亮保持 |
| 改一个两列表格单元格 | 只重排当前行两个单元格，普通行排版计数不增加 |
| 跨单元格选区 / 焦点变化 | 语法揭示及时变化，无陈旧的单元格布局 |
| 缓存命中后的输入 | 原生输入接口继续工作，组合输入提交可一次撤销 |
| 变宽、文字大小、主题 | 布局失效而文档结构缓存不丢失，文本保持一致 |
| 文件同步 | 真实临时文件覆盖、原子替换和删除均触发读取；冲突 / BOM / CRLF / 无效 UTF-8 保护继续通过 |
| 普通段落统计 | 只计数修改的一行，不重复生成大纲；结构编辑 / 撤销结果与全文扫描一致 |

用户指定的文档通过可选输入 `TINY_MD_PERFORMANCE_DOCUMENT` 只读加载：593 行、24 个表格。
1080 × 700 测试窗口下，一次向下滚动 4000 px 构建 **63 个行节点，0 次文本排版**；
普通段落单字符输入产生 **1 次行排版，0 次表格单元格排版**。
这与优化前每次调用 1272 次 `shape_text` 的工作量有明显差别，但两个数字分别来自 TestPlatform 回归和原生诊断，
不应推导原生耗时下降比例。

$env:TINY_MD_PERFORMANCE_DOCUMENT = 'D:\project\zero2one\docs\1. 0-1立项工具产品定义与共创工作流-V2.0.md'
cargo test --locked -p tiny-md-editor long_document_scroll -- --nocapture

## 原生复测状态

本轮 Computer Use 在获取隔离验证窗口时被用户物理 Escape 中止，随即停止原生 UI 操作。
因此没有优化后 Windows 原生 CPU 路径 P50 / P95、GPU 帧率或滚动录像证据；
优化前 P95 14.069 ms 的记录保持不变，不能声称已经达到建议的 P95 < 8 ms。
真实中文候选位置、Windows 字体实际绘制、长图滚动和用户主观流畅度仍需原生复测。
