## 范围与行为

帮助菜单提供“检查更新”和“版本变更日志”。更新窗口显示当前版本、目标版本、用户变更日志、
下载进度，以及下载、取消、重试和“安装并重启”入口。用户分别确认下载与安装，
自动检查不会自行下载、替换或重启应用。

参考 ashell 提供启动检查、按间隔检查、关闭自动检查三种偏好，默认启动检查；
间隔限制为 1–8760 小时，最后检查时间与偏好保存到本机配置目录。
自动检查不阻塞编辑，没有新版本时不弹窗；离线、超时、限流或没有发布版本时不影响写作。
手动检查反馈明确结果。请求仅用于版本与发布附件，不上传文档、路径或编辑内容。
开发构建只支持手动检查和下载，不运行自动检查，也不能执行安装。

新版本按 SemVer 比较；相同或较旧版本不更新，预发布和草稿不进入稳定版更新通道。
只接受当前平台与架构的精确安装包名，不回退到其他平台产物。
只读版本与日志以编译时 `CARGO_PKG_VERSION` 和对应发布正文为准。

## 发布来源与下载

参考 ashell 使用三级元数据来源：

1. 优先请求 `https://github.com/ynx-official/tiny-md/releases/latest/download/update-manifest.json`。
2. 清单不存在、网络错误、限流或服务器故障时，回退到 GitHub Releases API。
3. API 因网络、限流或服务器故障不可用时，使用 GitHub latest 发布页面确定标签，
   再从该标签的附件获得清单或校验和。页面结构不符合预期时报告失败，不猜测版本或哈希。

清单采用 `schema_version`、`version`、`notes_url`、`assets` 字段，每个附件包含
`name`、`url`、`size`、`digest`，与 ashell 的 schema 1 相同。
只允许本仓库对应版本的精确附件地址，日志 URL 同样限制到本仓库的 `release-notes.md`。
完整响应已取回但含不支持 schema、非法地址、错误 digest 或重复附件时直接拒绝，
不把校验错误当成网络故障降级。

下载在后台进行并支持取消；重复检查或下载不启动第二个并发任务。更新包通过 HTTPS
从该仓库的 Release 附件地址下载，GitHub CDN 重定向仍须使用 HTTPS。
下载具有超时、长度上限、临时文件清理和精确的文件长度检查。缺少校验和、长度不符或 SHA-256
不匹配时，禁止执行安装包并展示可重试错误。安装前再次核验已暂存产物。
相比参考项目的内存缓冲方式，本项目将下载流写入独占临时文件并同步计算 SHA-256，
避免大安装包占用与其大小相同的内存。解包拒绝路径穿越、符号链接和超限条目，
只接收固定布局的应用或可执行文件。

## 安装、退出与恢复

下载成功后用户选择“安装并重启”。更新退出检查逐窗口处理未保存内容，
取消、保存失败或磁盘冲突时终止安装。仅在所有窗口同意后创建安装交接，
不得先启动等待进程退出的助手再提示保存，否则取消后正常退出可能意外触发安装。
若保存过程中用户继续修改其他窗口，安装交接前再次核对全部窗口状态。

Windows 通过与当前可执行文件路径一致的 Inno 卸载注册信息识别安装版，
安装版下载现有 `-setup.exe`，便携版下载新增的 `-portable.zip`。
本地隐藏助手等待旧进程退出；安装版使用当前用户权限和原安装目录调用 Inno Setup，
便携版在原目录暂存、备份和替换可执行文件。助手核验结果，成功后重新启动应用，
替换失败恢复备份并保留诊断日志。只执行本地固定参数，不执行远端提供的命令。
不得强制关闭其他 Tiny MD 进程；文件仍被其他实例占用时停止安装并保留旧版本。

助手使用当前应用可执行文件的临时副本，通过 `--apply-update` 在 GPUI 初始化前执行。
父进程必须收到助手的就绪确认后才退出；助手再次校验归档、解包与版本。
Windows 等待与进程探测使用固定 PowerShell 脚本及独立路径参数，应用替换在 Rust 中完成，
成功后由受限清理脚本删除本次独占临时目录。跨重启失败日志位于该临时目录的 `install.log`。

2026-10-09 根据用户报告“Windows 点击更新后重新打开旧版”修订安装交接：
助手在退出确认前检查路径类型，调用 Inno Setup 6 前将 Rust canonicalize 的 `\\?\` 磁盘路径
和 `\\?\UNC\` 共享路径转换为普通绝对路径；保留 UTF-16 文件名和独立参数传递。
安装改用 `/SILENT`，自动安装期间显示进度窗口，继续禁止系统重启和强制关闭其他实例。
安装器另写 `installer.log`；非零退出或版本不符恢复应用文件后，由原生对话框反馈失败与日志位置。
备份覆盖可执行文件、已有 `version.txt` 与 `welcome.md`，不宣称回滚安装器的全部注册表状态。

旧版本复制的是旧助手，单改新版助手无法修复它首次升级时的路径。
新安装包因此包含 `scripts/windows-update-compat.iss`，在目录验证前规范化旧助手传入的目录。
原 `v0.2.0` / `v0.2.1` 附件保持不变，修复随新的正式版本交付。
发布检查新增隔离安装版助手成功、旧参数兼容、失败恢复和其他实例保护，
具体证据见 [Windows 安装版更新修复](../04-quality/windows-installed-update.md)。

macOS 保留 DMG 用于首次安装，增加包含已签名应用 bundle 的便携 ZIP 用于更新。
仅识别当前运行的 `Tiny MD.app`，在其旁边暂存完整新 bundle、校验版本与 bundle 标识，
由本地助手等待旧进程退出后备份、替换并重新打开应用；替换或启动失败时恢复旧 bundle。
不可写目录和直接从 DMG 运行的应用反馈明确错误，提供原有 DMG 手动安装入口。
本轮不增加 PKG、管理员权限安装、Linux、Intel macOS 或 Apple 开发者签名与公证。

重启回到写作窗口；跨重启恢复未命名文档、光标或撤销历史不在本轮范围，
因此未命名文档必须先保存或由用户明确放弃。

## 模块边界与信任边界

- 独立无 UI 的更新模块负责版本判定、发布响应验证、HTTP 下载与校验；不接触文档内容。
- `crates/app` 负责 GPUI 菜单、提示、任务状态与安装交接。
- Windows / macOS 的进程启动、安装探测与替换助手封装限制在平台边界内。
- 现有 `document` / `editor-adapter` 不承担更新职责。
- 信任 GitHub 发布仓库和 TLS。SHA-256 用于完整性校验，不等于独立的发布者数字签名。
  不增加独立签名密钥；发布者签名、公证、静默下载和强制更新不属于本轮范围。

## 版本与变更日志的唯一来源

工作区 `Cargo.toml` 是应用版本的唯一来源，应用关于信息读取编译版本。
发版标签必须等于 `v` 加工作区版本；预发布版本保留完整 SemVer 后缀，平台包元数据按平台要求取核心版本。

参考 ashell 的发布文档分工，按本项目的 `docs/` 分类规范调整路径：

- `docs/06-delivery/versions/vX.Y.Z.md`：该版本的唯一详细说明，记录用户变化、兼容性、
  升级说明、已知问题、真实验证结果和变更依据。
- `docs/06-delivery/versions/index.md`：代码版本和历史索引，明确区分已发布与待发布。
- 根目录 `CHANGELOG.md`：精简用户摘要与详情链接，未发布变更归入 `Unreleased`。
- `scripts/release_notes.py`：核对工作区版本、所有 workspace 包的锁文件版本、标签、
  日期、详情和索引，从详情生成 `release-notes.md`；不把提交标题当作用户变更日志。
- `scripts/update_manifest.py`：校验目标平台产物集合，计算大小与 SHA-256，生成更新清单。

Release Notes 和客户端日志采用同一份 `release-notes.md`，排除详情中的验证记录、
变更依据与站内导航。应用内当前版本日志在构建时提取同一正文。
准备发版才升级版本，未完成的新功能不写成已发布；不虚构历史日期或原生验收结果。

发布工作流先运行发布工具测试与资料一致性检查，再构建两个平台安装包和便携更新包、计算校验和。
所有附件上传完毕后才将新 Release 从草稿发布，避免客户端发现半成品版本。
重跑必须保持已发布版本附件一致，不允许悄悄替换同版本代码。

## 验收标准

1. 测试覆盖版本大小、预发布过滤、草稿过滤、平台选择、非法下载地址、缺失与重复附件。
2. 测试覆盖三级来源回退与校验失败不降级、离线 / 超时 / HTTP 错误、下载截断、
   长度超限、错误哈希、取消、临时文件清理与重复任务保护。
3. 更新检查与下载不阻塞编辑；安装前未保存提示的取消和保存失败不会创建安装助手。
   暂存路径含空格和引号仍可安全传参，替换失败能够恢复旧版本，安装版与便携版不会混选。
4. 应用显示的版本、安装包版本、标签和日志版本一致；缺失日志或版本不一致时发布检查失败。
5. Release 正文与对应变更日志章节一致，客户端不接受未校验的安装包。
6. 运行 Windows 相关测试、格式检查、Clippy 和构建，记录实际证据；macOS 原生安装交互单独记录验收状态。
