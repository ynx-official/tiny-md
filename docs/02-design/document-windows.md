# 文档窗口与打开行为

- 状态：Review
- 最后更新：2026-10-08
- 关联文档：[UI 风格](ui-style.md)、[外部文件同步](external-file-sync.md)、[验证记录](../verification.md)

用户于 2026-10-08 明确要求：同时打开多个笔记时，每篇笔记使用独立窗口，不能替换正在阅读的笔记。

## 打开规则

- “文件 → 打开”、打开最近文件、侧栏文档列表 / 文档树点击、右键“打开”均在新窗口打开笔记。
- 文件对话框允许一次选择多篇笔记，每个成功读取的文件各创建一个窗口。
- 原窗口保留文档路径、正文、未保存内容和撤销历史；打开其他笔记不要求保存或放弃原笔记。
- 取消选择不改变原文档。文件读取失败时在原窗口显示错误，不创建该文件的窗口；批量选择中的其他有效文件继续打开。
- 新窗口复用现有写作布局。若目标文件位于原窗口的文档目录范围内，新窗口保留该目录作为文档树根节点。
- 每个窗口独立保存和关闭；关闭有修改的窗口时仍需保存、放弃或取消，其他文档窗口继续保留。
- “从磁盘重新加载”更新当前窗口中的同一文档，有未保存内容时继续使用原有保存检查。

## 实现与验收

打开入口仍使用 `Intent::Open` / `Intent::OpenPath`，在后台读取文件后构建新文档窗口；
`Intent::Reload` 单独管理当前窗口的磁盘重新加载。各窗口继续登记到会话中，沿用退出和更新安装的逐窗口检查。

回归覆盖普通打开、未保存内容与撤销历史、最近文件、右键打开、侧栏点击及目录范围、
批量读取中的部分失败、关闭取消与放弃、空选择、重新加载及取消保护。
GPUI TestPlatform 的渲染和事件检查验证上述行为；Windows / macOS 原生多选对话框、窗口焦点及系统关闭交互仍需实际验收。
