# 文档窗口与打开行为

- 状态：Review
- 最后更新：2026-10-09
- 关联文档：[UI 风格](ui-style.md)、[外部文件同步](external-file-sync.md)、[验证记录](../verification.md)

用户于 2026-10-08 明确要求：同时打开多个笔记时，每篇笔记使用独立窗口，不能替换正在阅读的笔记。
用户于 2026-10-09 补充：未命名且没有需要保存的内容时，应默认复用当前窗口，避免留下多余空窗口。
用户同日进一步明确：左侧文档列表和文档树打开文件属于当前窗口切换，不使用上述默认新窗口规则。

## 打开规则

- “文件 → 打开”、打开最近文件和拖放使用相同的窗口选择规则：当前文档没有文件路径、正文完全为空且没有待保存修改时，在当前窗口打开；其他情况创建新窗口，保留原文档与草稿。
- 左侧文档列表 / 文档树点击与其中右键“打开”在当前窗口切换文件。当前有未保存修改时提示保存、放弃或取消；取消或保存失败保留当前文档及修改。
- 文件对话框允许一次选择多篇笔记。若当前窗口可复用，第一个成功读取的文件使用它，其余成功文件各创建一个窗口；读取失败不占用这个复用机会。
- 文件菜单、最近文件和拖放不会因为已打开文件内容为空或未保存标记尚未刷新而替换原文档。侧栏显式“在新窗口中打开”继续创建新窗口。
- 创建新窗口时，原窗口保留文档路径、正文、未保存内容和撤销历史，不要求保存或放弃原笔记。
- 取消选择不改变原文档。文件读取失败时在原窗口显示错误，不创建该文件的窗口；批量选择中的其他有效文件继续打开。
- 新窗口复用现有写作布局。若目标文件位于原窗口的文档目录范围内，新窗口保留该目录作为文档树根节点。
- 每个窗口独立保存和关闭；关闭有修改的窗口时仍需保存、放弃或取消，其他文档窗口继续保留。
- “从磁盘重新加载”更新当前窗口中的同一文档，有未保存内容时继续使用原有保存检查。

## 实现与验收

打开入口仍使用 `Intent::Open` / `Intent::OpenPath`，在后台读取文件后检查当前编辑器，复用空白未命名窗口或构建新文档窗口；
`Intent::SwitchPath` 管理侧栏当前窗口切换，`Intent::Reload` 管理磁盘重新加载，两者都经过未保存检查。
各窗口继续登记到会话中，沿用退出和更新安装的逐窗口检查；切换目录内文件时保留文档树根目录。

批量读取中的部分失败、关闭取消与放弃、空选择、重新加载及取消保护。

同日按用户补充调整侧栏验收：列表、树和右键默认在当前窗口加载，验证取消保留、放弃后切换、保存原文档后切换，以及显式新窗口仍保留原文档。
