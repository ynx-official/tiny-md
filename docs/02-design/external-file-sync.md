## 用户行为

用户要求其他应用修改文件后，Tiny MD 能同步内容，不再只报保存失败。
以下按行合并与冲突选择是本轮采用的最小实现方案。

- 已打开文件监听父目录的文件事件，每 150 ms 检查合并后的待处理标记并在后台读取。
  无事件时每 5 秒完整核对字节，监听不可用时也采用此兜底；没有本地修改时，直接同步磁盘内容。
- 有未保存修改时，以最近读入或保存的版本为共同基准进行三方合并。不同区域的修改自动合并，
  合并后的本地修改仍显示未保存，只有用户保存才写入磁盘。
- 同一处修改重叠时，不覆盖双方内容，不向文档插入冲突标记。底栏显示“处理同步冲突”，
  保存时也会提示“另存为本地副本 / 同步磁盘版本 / 取消”。
- 另存副本默认建议 `原文件名-本地副本.md`，原磁盘文件保持其外部修改。
- 明确选择同步磁盘版本时重新读盘，以一次可撤销编辑更新内容。Ctrl+Z 可恢复本地版本；
  此选择会中止正在进行的关闭 / 退出流程，保留编辑窗口供继续检查。
- 中文输入法组词及文件对话框、保存等操作期间暂停自动同步。后台结果若遇到新输入、
  更换文档或较新的保存基准则丢弃，并保留重试标记。

## 状态与保存

`Document` 以共享不可变快照保留规范化的 LF 保存基准与磁盘原始字节，克隆不复制全文，实时文本由编辑器持有。
同步检测包含 BOM 或换行格式的变化；新基准保留外部版本的 BOM 和统一 CRLF 格式。
合并使用锁定版本 `diffy 0.4.2` 的三方按行合并，遇到冲突只返回错误。

保存路径使用独立的 `save_synchronized` / `save_as_synchronized` API，保存前再次读取并合并，
因此不依赖文件事件恰好及时完成。读盘与保存检查之间再次变化时，最多重新核对三次。
严格的 `save` API 仍拒绝直接覆盖外部修改；另存为同一文件也执行同步与冲突保护。
保存使用同目录临时文件与原子替换，整个操作成功后才更新保存基准。

编辑器以一次差异替换记录同步，保留之前的撤销历史、未改变区域的光标 / 选区以及滚动位置。
删除的行或变短的内容会将位置收敛到有效范围。切换到另一文档仍按原规则重置该文档的编辑历史。

## 验收与边界

自动回归覆盖：干净版本更新、独立修改合并、相同修改、重叠冲突不覆盖、同目标另存保护、
本地副本、UTF-8 / emoji、BOM / CRLF、删除或无效 UTF-8 保留状态、同步后的撤销、反向选区与光标映射。
原生端应再检查外部编辑实际读入、底栏冲突入口、三项提示及保存后的文件内容。

正常事件在后续检查中处理；事件缺失时更新可能等待 5 秒的字节核对。
父目录监听覆盖编辑器原子替换，并合并连续事件以限制积压。
合并按行处理，同一行中不同位置的修改可能仍被视为冲突。
尚未提供对照合并编辑器、自动保存或崩溃恢复。撤销记录只保留在当前窗口会话内。
保存检查和原子替换之间仍存在极短竞争窗口，不构成其他应用也遵守的跨进程文件锁。
文件被删除、暂时不可读或包含无效 UTF-8 时显示错误，保留本地编辑，不自动创建替代文件。
