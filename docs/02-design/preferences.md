并提供 Typora 的左侧分类 / 右侧设置截图作为布局参考。

本轮实施取舍是先集中目前已有的全局设置，分为“外观”和“更新”两类。
参考图用于分类布局，未把图片、导出、自动保存或恢复草稿等尚未实现的能力添加为控件。
编辑、源码、专注、打字机、侧栏等当前窗口的即时操作继续保留原有菜单与行为。

## 偏好设置

- 文件菜单提供“偏好设置…”，Windows 使用 Ctrl+,，macOS 使用 ⌘,，均可从任意窗口触发。
- 独立窗口默认 780 × 540 px，最小 640 × 430 px；左侧暖灰分类栏，右侧选项区可滚动，底部固定“完成”。
- 重复打开复用同一窗口；从更新窗口进入时直接选中“更新”分类。
- 用户于 2026-10-28 要求默认跟随电脑，替代原默认浅色规则。“外观 → 夜间模式”提供“黑夜 / 白天 / 跟随电脑”，应用到所有文档及工具窗口，立即生效并在下次启动保留。
  缺少配置或未设置主题时默认“跟随电脑”；跟随模式响应系统外观变化，黑夜 / 白天固定使用对应主题。原主题菜单同步显示三项，并按保存的模式勾选，不能把当前显示的颜色误当作固定模式。
  已打开的流程图窗口界面也跟随全局主题，图形保留原有只读快照。
- “更新”提供启动时 / 按间隔 / 关闭。选择按间隔后显示小时输入，范围 1–8760；
  按 Enter 或点击“保存间隔”后应用，非法或不完整输入不会改变已保存值。
- 检查频率仍由原更新定时器读取，不重置最后检查时间。
- 新增“后台自动下载”开关，默认关闭。开启后手动或自动检查发现新版会后台下载，
  校验完成再弹出更新页；安装仍需确认。关闭时取消正在进行的自动下载，手动下载继续。
- 主题存于原配置目录中的 `preferences.json`，更新仍使用 `update-settings.json`，无旧更新设置迁移。
  `auto_download` 字段缺省为 false，旧配置保留检查模式、间隔与最后检查时间。
  两者使用独占暂存文件、同步写入和原子替换；保存成功后才更新内存中的生效值。
- 主题配置使用 `theme: "dark" | "light" | "system"`。兼容旧 `dark` 布尔值：true / false 分别保留为黑夜 / 白天，新字段优先；读取不重写文件，下次主动修改才保存新格式。旧版本只有用户主动选主题才写入该布尔值，因此不重置已有手动选择。
- 读取损坏的主题配置时保留原文件并显示提示，使用默认跟随电脑；修改失败显示原因，旧配置保持可用。
- 切换主题或打开设置不会修改笔记内容、草稿、撤销历史或写作模式。

### 夜间模式实现与验证（2026-10-28）

`preferences.rs` 区分保存的模式和当前生效的深浅色；启动时使用 GPUI 的系统外观解析默认模式。文档、偏好设置、更新和流程图窗口共用 GPUI 外观事件监听，事件只刷新实际颜色，不把系统变化写成手动偏好。重新创建窗口时重新读取其系统外观，覆盖应用没有打开窗口时错过系统通知的情况。macOS 的普通 / vibrant 深浅外观均映射到对应模式。

顶部主题菜单与偏好设置共用保存与应用路径。即使当前已显示白天，主动选“白天”也会退出跟随模式；切回“跟随电脑”立即解析当前电脑外观。保存成功后才更新全局主题，写入失败保留原模式与原颜色。

先实际运行失败回归，复现默认选中“浅色”而非“跟随电脑”；另一个失败回归复现新窗口沿用过期深色状态。新增验证覆盖三档持久化、旧配置迁移、新字段优先、系统事件与固定模式、多窗口主题同步、两端主题菜单勾选、同色手动选择、原子保存失败及新窗口重新解析外观。

自动系统事件回归使用共享处理函数和 GPUI TestPlatform；不等同于 Windows / macOS 实际操作系统主题热切换或原生下拉菜单验收。本次没有修改电脑的系统外观设置。

实际运行 `./scripts/check.ps1` 通过：301 项工作区测试（应用 80、文档 16、编辑器 190、更新器与集成测试 15）、17 项发布工具测试、版本资料检查、格式检查与 workspace all-targets Clippy；原有两项手工性能测试和一项 doctest 仍忽略。Windows 开发版 `cargo build --locked -p tiny-md` 成功。日志为 `target/night-mode-check.log` 和 `target/night-mode-build.log`，没有发布或替换已安装版本。

## 更新窗口

用户于 2026-10-09 对落地截图提出重新设计，修订此前上下分区与底部主操作方案。
沿用 680 × 610 px 的独立窗口和 520 × 400 px 的最小尺寸；新方案采用 32 px 水平留白：
顶部以应用名、简洁版本标记和发布日期组成版本区，右侧显示当前主要操作，下一行呈现真实状态。
未发现新版时直接显示离线当前版本日志，不显示会误导的“新版本”标签。
发现新版后，在日志标题右侧显示无边框的轻量切换项；日志标题标注当前阅读的版本。
日志独立滚动和选择复制，深浅色及两个日志标签分别保留渲染状态。
只移除本项目生成日志开头的重复版本标题和日期；保留正文中的标题、引用、列表、强调、代码和表格。

检查 / 下载 / 取消 / 安装并重启始终位于版本区右侧，底部改为 52 px 白色工具条，
仅保留更新设置、发布页面与关闭。移除厚重灰色页脚和选中标签的整圈黑框，
开发构建的安装限制仅在准备安装时提示，不在空闲页反复展示。
状态使用小圆点与简短文案，明确区分发现版本、后台下载、校验与“更新已准备好”；
实际百分比、文件大小与进度条独立于状态文字，新版发布日期与当前版本清晰区分。
日志采用 14 px 正文、22 px 行高与更清晰的段落间隔，独立滚动。
底部“更新设置”直接打开相关分类，下载时可关闭页面继续写作，自动任务成功后再弹窗。
失败、取消或禁用自动下载后不弹窗；等待安装期间不重复检查或下载。频率与自动下载控件均在偏好设置。
原有校验、取消、失败重试、开发构建禁止安装、逐窗口未保存检查和助手交接保持原流程。
