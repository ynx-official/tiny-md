## 需求与范围

用户反馈“文件 → 打开最近文件”列表为空，明确要求记录持久化到本地，并提供 Typora 菜单截图作为样式参考。
原实现只保留当前进程中的 5 个路径，退出即丢失；空列表没有提示。

本次实现采用 20 条上限，按最近成功打开或保存的顺序排列，重复路径移到首位。
该上限是实施默认值。截图中的“重新打开关闭的文件”属于独立的关闭记录功能，本次不加入。

## 行为

- 启动读取本地记录。启动参数打开、文件选择器、拖放、侧栏切换、新窗口打开，以及保存 / 另存为成功后更新记录；取消和失败不加入文件。
- 记录规范化的绝对路径。同一个 Windows 文件的普通路径、短名称路径和扩展长度路径不会因为保存后重新打开而重复。
- 应用内重命名同步改写原记录；移到回收站成功后移除记录。复制操作在副本真正打开或保存后才加入副本。
- Windows 与 macOS 共用存储和菜单动作。各文档窗口在记录变化后刷新菜单；菜单动作携带具体路径，不依赖可能变化的列表序号。
- 点击历史文件沿用文档窗口规则：复用干净的空白未命名窗口，其他情况创建新窗口，保留已有笔记与草稿。
- 暂时不可用的外部磁盘路径保留；启动不探测所有历史文件。点击缺失文件显示打开失败，当前文档保留。
- “清除最近文件”立即清空本地历史与会话列表，不删除磁盘文档、不关闭窗口、不修改正文或撤销栈；清除写入失败时保留列表并提示原因。

## 菜单样式

沿用 notion 的原生紧凑菜单、细分隔线与主题颜色。文件路径一行一项，长路径省略中间部分；Windows 扩展路径前缀仅在显示时隐藏，不改写实际打开路径。
Windows 子菜单根据窗口宽度限制宽度，超高时滚动，悬停可读完整路径。底部分隔线之后提供“清除最近文件”。
没有记录时显示禁用的“暂无最近文件”。清除入口仍保留，以便用户显式重置损坏的历史文件。

## 本地存储与错误

- Windows：`%LOCALAPPDATA%/Tiny MD/recent-files.json`。
- macOS：`~/Library/Application Support/Tiny MD/recent-files.json`。
- JSON 对象包含 `paths` 数组，只记录文件路径，不复制文档正文，不上传网络；与主题、更新配置分别保存。
- 每次变更采用同目录独占临时文件、同步写入和原子替换；通过 `recent-files.lock` 的系统文件锁保护读改写，在锁内读取最新记录，避免独立进程覆盖新记录或恢复已经清除的旧历史。记录写入失败不撤销已经成功的文档操作，会话历史仍可用，底栏显示“最近文件记录异常”，悬停可看原因。
- 损坏 / 无法读取的原记录保留，不在打开文件时覆盖。用户显式清除成功后恢复正常写入；没有历史文件时正常使用空列表。
- 旧版没有落盘记录，因此无法恢复旧版退出前已经丢失的历史，需要在新版中重新打开文件开始积累。
